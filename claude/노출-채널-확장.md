# 노출 채널 확장 — 구축 기록 (2026-08-06)

블로그·인스타 릴스 외 노출 채널을 늘리기 위한 인프라. **새 콘텐츠를 만들지 않고 기존 산출물의 배포처만 늘린다**는 것이 이 문서 전체의 원칙이다. 매일 만드는 글 1편·영상 1개가 지금은 2곳에 나가는데, 아래가 다 붙으면 6곳이 된다.

## 왜 이 방향인가

2026-08-06 Ahrefs 실측에서 구글 헤드 키워드 총량이 월 11,020건(양도세 4,470 + 증여상속 5,260 + 취득재산 1,290)으로 확인됐다. 전 키워드 1위를 해도 월 3,300명이 상한이다. **세목을 늘려서 메울 수 있는 격차가 아니므로 채널을 늘려야 한다.**

같은 날 확인된 백링크 실측도 이 판단을 뒷받침한다 — 세꼼이 백링크 160개가 전부 스팸 플래그·전부 nofollow·전부 홈페이지 대상이었다. 실질 링크 0, 링크받은 글 0편. 도메인 권위가 없는 국면에서는 검색 외 경로가 더 빨리 작동한다.

---

## 1. 구축 완료 (2026-08-06)

### 1-1. RSS 피드 — `scripts/build-rss.cjs`

`public/blog/index.html` 의 ItemList JSON-LD 를 파싱해 `public/rss.xml` 을 생성한다. 최신순 30편, pubDate 는 `sitemap-blog.xml` 의 lastmod 참조.

RSS 자체의 직접 유입은 작다. **이건 외부 배포 자동화의 배관이다.** 뉴스 애그리게이터 수집, 스레드/X 자동 게시 트리거, 뉴스레터 자동 발행이 전부 RSS 를 소스로 삼는다. 채널을 늘릴 때마다 파서를 새로 만들지 않아도 된다.

`public/robots.txt` 에 `Sitemap: https://sekkomi.com/rss.xml` 을 추가해 구글이 RSS 도 색인 소스로 쓰게 했다(구글은 RSS 를 사이트맵으로 인정한다).

### 1-2. 구글 디스커버 대응 — `scripts/build-seo-meta.cjs`

배포 때마다 `public/blog/*.html` 에 세 가지를 자동 주입한다. **새 글을 쓸 때 신경 쓸 것이 없도록** 발행 세트(4점)는 그대로 두고 여기서 일괄 보정하는 구조다.

1. **`max-image-preview:large` robots 메타** — 디스커버는 큰 이미지 카드로만 노출되는데, 이 지시자가 없으면 썸네일 크기로 제한돼 사실상 후보에서 빠진다. **도입 전 47편 중 0편이 갖고 있었다.** 디스커버 진입의 선결 조건.
2. **RSS 대체 링크** — `<link rel="alternate" type="application/rss+xml">`
3. **글 전용 og:image 자동 교체** — `public/reels/<id>_og.jpg` 가 있으면 og:image·twitter:image 를 그것으로 바꾼다. 슬러그 매칭은 큐 JSON 의 `blog_url` 로 한다(릴스 id 와 글 슬러그가 다르기 때문).

빌드 로그에 **공유 히어로(`hero_1sedae.png`) 사용 글 목록**을 출력한다. 도입 시점 21편 — 같은 이미지를 20편 넘게 돌려쓰면 디스커버 후보에서 빠지므로 순차 교체 대상이다.

### 1-3. 글 전용 OG 카드 생성 — `tools/shortform/og_render.py` + `og_card.html`

릴스 큐의 훅 문구를 읽어 1200×630 카드를 Playwright 스크린샷으로 만들어 `public/reels/<id>_og.jpg` 에 저장한다. 디자인은 세꼼이 브랜드(다크그린 #163300 / 라임 #9FE870) 그대로.

**호출 지점이 중요하다.** 자동화 토큰에 `workflow` 스코프가 없어 `.github/workflows/` 는 403 으로 못 건드린다(2026-08-05 재확인). 그래서 워크플로가 렌더 직후 이미 호출하는 `scripts/reel-queue-add.cjs` 에 훅을 걸었다. 워크플로는 `git add public/reels` 로 디렉터리를 통째로 커밋하므로, 여기에 파일을 쓰면 **워크플로 파일 수정 없이** 산출물이 함께 커밋된다.

**백필 로직 포함** — 매 실행마다 큐 전체를 훑어 `_og.jpg` 가 없는 항목을 함께 생성한다. 워크플로의 렌더 대상 판정은 mp4 유무만 보므로, 이게 없으면 기능 도입 이전 글들은 영원히 OG 카드를 못 받는다.

문구 우선순위: 큐 JSON 의 `og_headline` → 큐 HTML 카드1(훅) 텍스트. 둘 다 없으면 생성을 건너뛴다. 34자를 넘으면 폰트를 한 단계 줄인다.

### 1-4. 안전 원칙 (기존 `build-*.cjs` 관례 유지)

- 전부 자기완결형(idempotent) — 여러 번 실행해도 중복 주입되지 않는다
- 어떤 오류가 나도 원본을 건드리지 않고 조용히 종료, `netlify.toml` 에서 `|| true`
- OG 생성 실패는 릴스·커밋 파이프라인을 막지 않는다 (항상 exit 0)

## 2. 다음 단계 (자격증명 1회 필요)

### 2-1. 유튜브 쇼츠 자동 업로드 — 가장 우선

**mp4 도 캡션도 이미 있다.** `claude/숏폼-제작-기준.md` 에 "인스타·유튜브 쇼츠·틱톡 3플랫폼 공용" 이라고 이미 적혀 있는데 실제로는 인스타에만 나가고 있다.

도달보다 **검색**이 진짜 이유다. 유튜브는 세계 2위 검색엔진이고 유튜브 영상은 구글 SERP 에도 올라간다. 2026-08-06 실측에서 `증여세율`·`상속세율`·`양도소득세`·`양도세율` SERP 에 Video preview 기능이 붙어 있음을 확인했다 — 블로그로는 못 들어가는 자리인데 쇼츠로는 들어간다.

- 구현: `netlify/functions/publish-reel.js` 와 같은 패턴의 함수 1개. YouTube Data API v3, 일일 할당량 10,000유닛 / 업로드 1건당 1,600유닛이라 하루 1편은 여유롭다.
- **오너 1회 작업**: Google Cloud 프로젝트 → YouTube Data API v3 활성화 → OAuth 클라이언트 생성 → refresh token 발급 → Netlify 환경변수(`YT_CLIENT_ID`, `YT_CLIENT_SECRET`, `YT_REFRESH_TOKEN`) 등록. 인스타와 동일하게 `YT_PUBLISH_ENABLED=1` 게이트를 둔다.
- **지금 바로 가능한 것**: 유튜브 채널 개설 + 브랜드 설정(채널명·프로필·배너·설명에 sekkomi.com). 이미 렌더된 mp4 3개를 수동으로 올려두면 채널 초기 신호가 생긴다.

### 2-2. 스레드(Threads)

메타 API 라 **인스타 토큰 인프라를 그대로 공유한다.** `claude/인스타-자동게시-셋업.md` STEP 1~5 로 토큰을 발급하면 함수 1개 추가로 끝난다. 텍스트 기반이라 세금 정보와 궁합이 좋고 증분 비용이 사실상 0.

### 2-3. 틱톡

Content Posting API 는 있으나 앱 심사가 필요해 앞의 것들보다 무겁다. 유튜브가 붙은 뒤에.

## 3. 자동화하지 않는 것 (의도적 제외)

### 커뮤니티 자동 게시·자동 댓글 — 금지

뽐뿌·82쿡·다모앙·부동산 카페는 이 니치에서 실제로 링크가 생기는 곳이다(2026-08-06 Ahrefs Link Intersect 에서 확인). 그러나 자동화하는 순간 계정이 날아가고 도메인이 스팸으로 기억된다.

**대신 반자동으로 한다**: 데일리 자동화가 "오늘 답변할 만한 질문 3건 + 그 조건으로 실제 계산한 결과 초안"을 데일리 보고 메일에 넣고, 오너가 5분 안에 붙여넣는다. 계산이라는 진짜 가치를 주는 답변이라 스팸이 아니다.

### 네이버 블로그 — 보류

공식 글쓰기 API 가 없어 브라우저 자동화밖에 없는데 네이버가 이를 탐지한다. 같은 글을 그대로 올리면 원본(sekkomi.com)과 중복 콘텐츠가 된다. **2026-08-10 네이버 서치어드바이저 검증 결과를 보고** 요약 + 원문 링크 형태로 수동 운영할지 판단한다.

### X(트위터)

한국 부동산 세금 타깃층(40~60대 유주택자)이 거의 없다. 우선순위 최하위.

## 4. 검증 기록 (2026-08-06)

- 클린 클론에서 전체 빌드 체인 실행 통과 — `build-blog-featured` → `build-seo-meta` → `build-llms-txt` → `build-rss`
- `build-seo-meta` 멱등성 확인 — 2회차 실행 시 주입 0건
- 48개 파일에 robots 메타·RSS 링크 주입 확인
- `rss.xml` XML 파싱 유효, 30편 수록
- OG 카드 3장 생성 확인 (35~37KB, 1200×630), 백필 로직 동작 확인
- og:image·twitter:image 교체 3건 확인

**라이브 검증은 8/9 배포 재개 후.** 운영 규칙 §0.6 에 따라 크레딧 소진 구간에는 커밋만 하고 라이브 200 확인은 생략한다.
